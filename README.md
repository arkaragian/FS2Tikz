# FS2Tikz

Generate LaTeX TikZ diagrams of a filesystem tree. The tool walks a directory,
creates nodes for folders/files, and emits:

- a TikZ-only file (for inclusion in your own LaTeX docs)
- a wrapper `.tex` you can compile directly

## Features

- Recursive directory traversal
- Configurable include/exclude filters (files, directories, extensions)
- Built-in styles for common file types (e.g., `.sln`, `.csproj`, `.cs`, `.json`, `.pdf`)
- Produces a standalone wrapper for quick compilation

## Requirements

- .NET SDK 9.0+ (project targets `net9.0`)

## Build

```bash
# from repo root
dotnet build
```

## Usage

FS2Tikz exposes two subcommands:

- `dir <directory>`: quick generation with defaults
- `config <config.json>`: full configuration via JSON

All the examples bellow assume that the generated executable in your `$PATH`.

### 1) Quick run (directory)

```bash
# Generate TikZ for the current folder
FS2Tikz.exe dir .
```

Outputs (in the current working directory):

- `out.tex` (TikZ code only)
- `out_wrapper.tex` (standalone LaTeX wrapper)

### 2) Run with configuration file

```bash
# Generate TikZ with custom settings
FS2Tikz.exe config path/to/config/my-settings.json
```

#### Example configuration

```json
{
  "InputDirectory": "D:/source/repos/FS2Tikz",
  "OutputDirectory": "D:/source/repos/FS2Tikz/out",
  "OutputFileName": "tree.tex",
  "OutputWrapperName": "tree_wrapper.tex",
  "ExcludeFiles": [
    ".DS_Store",
    "Thumbs.db"
  ],
  "ExcludeDirectories": [
    ".git",
    "bin",
    "obj"
  ],
  "ExcludeExtensions": [
    ".user",
    ".cache"
  ]
}
```

Notes:

- `OutputDirectory` is optional; when omitted, files are written to the current working directory.
- File and directory excludes are by **name** (not full path).
- Extension excludes should include the leading dot (e.g. `.log`).

## Output

- `*.tex` files are generated by `libTikz`.
- The wrapper uses `\documentclass[tikz]{standalone}` and `\input{<tikz file>}`.

If you want to compile the wrapper directly:

```bash
# Example (choose your LaTeX toolchain)
pdflatex .\out_wrapper.tex
```

## How styles are chosen

FS2Tikz ships with built-in styles in hard coded into `libTikz`. Each file type
has a different `tikz` style.

| Item / File Type       | TikZ Style   |
| ---------------------- | ------------ |
| Directory              | `directory`  |
| `.sln`                 | `cssolution` |
| `.csproj`              | `csproject`  |
| `.cs`                  | `csfile`     |
| `.exe`, `.dll`, `.pdb` | `exefile`    |
| `.json`                | `jsonfile`   |
| `.pdf`                 | `pdffile`    |
| `CMakeLists.txt`       | `cmakelists` |
| Any other file         | `file`       |


You can tweak styles by modifying the definitions in `libTikz` (see `libTikz/libTikz/TikzPictureStyle.cs`).

## Project layout

```
FS2Tikz/              CLI entry point
libTikz/              TikZ model + renderer
```

## Troubleshooting

- If a path is invalid, FS2Tikz prints an error and exits.
- If no picture is produced (e.g., empty directory), the tool prints a message and exits.
